# Release note

Фрагмент импорта выписки. В сторы не публикуется.

## Разрешения

На Android нужен только `INTERNET`. Системный picker даёт доступ к выбранному файлу без разрешений на хранилище, поэтому всё, что приносят библиотеки, удалено из манифеста. `dumpsys` на Android 17 показывает ещё `ACCESS_LOCAL_NETWORK`, в манифесте приложения его нет.

На iOS разрешения не запрашиваются. `NSAllowsLocalNetworking` нужен только для HTTP к локальному mock.

Cleartext HTTP на Android включён и в release, потому что сервер здесь один и он локальный. В production его нужно отключить.

## Где остаются копии файла

| Что | Где | Когда удаляется |
|---|---|---|
| Копия файла | `caches/imports` | Как только сервер подтвердил job, при отмене, отклонении и ошибке. Забытые копии удаляются при следующем запуске |
| Первые 24 байта для проверки формата | `caches/imports` | Сразу после чтения |
| Копия picker на iOS | `tmp` приложения | Сразу после обработки выбора |
| Ключи, статус, отчёт | MMKV | После подтверждённого удаления импорта и нажатия «Готово», при закрытии экрана ошибки или при удалении приложения |
| Имя файла | MMKV | Как только известен job |

MMKV зашифрован демонстрационным ключом из `.env`, поэтому настоящей защиты нет. В production ключ нужно создавать на устройстве и хранить в Keychain и Android Keystore.

Кэш не попадает в резервную копию iOS, на Android `allowBackup=false`. Если ОС очистит кэш раньше времени, приложение попросит выбрать файл заново.

Системный журнал Android (`MediaProvider`) сам пишет путь файла при открытии. Приложение имя файла и содержимое не логирует.

## Как очистить данные

Готовый отчёт удаляется кнопкой «Удалить импорт»: она убирает данные с сервера, а после подтверждения «Готово» очищает их на телефоне. Экран ошибки закрывается своей кнопкой. Всё локальное исчезнет при удалении приложения или очистке его данных в настройках Android, но данные на сервере при этом останутся.

## Что остановит rollout

- Больше одного `newJobs` на подтверждённую пользователем отправку: возможны дубли.
- Импорты, которые долго остаются в «Результат отправки неизвестен» или «Импорт не удалён».
- Имя файла или содержимое в логах и crash-отчётах.

Телеметрии здесь нет, в production эти сигналы сначала придётся собирать.

## OTA или новый бинарник

Через JS/OTA можно доставить весь `src/`: экраны, тексты, логику повторов и ревизий.

Новый бинарник нужен для патча `react-native-blob-util` в `client/patches`, обновления нативных модулей и React Native, правок манифеста, `Info.plist` и иконок. Значения `.env` тоже требуют пересборки, потому что `react-native-config` встраивает их при сборке.
